## 0. 撤回声明（v1 错在哪）

| v1 的说法 | 审计结论 | 处置 |
|---|---|---|
| "24 条 canary 覆盖路径/uuid/hex/ENV/错误串六类" | **假的**。实际 24 条 = 18 条 volpath + 6 条 filepath，**100% 是路径**；uuid/hex/ENV/error 因排在正则模式序末尾被结构性排除 | 撤回 |
| "脚本随机抽，不人工挑" | **假的**。`step = floor(38/24) = 1`，等于按模式序取前 24 条，确定性且非随机 | 撤回 |
| canary 命中数可比 | **可被游戏**。锚点层层嵌套，`/vol3/1000/work` 是另外 12 条的子串，**9 条字面量 / 616 字符即可打满 24/24**；有效自由度只有 9 | 撤回，换仪器 |
| "同样成本" | **不成立**。token 95% CI = −40.5% … +44.4%（Welch p≈0.90）；要 ±10% 精度需 N≈50 | 撤回 |
| "lcm 更省 / 0.98×" | **符号反了**，实际 1.019×；且计入 prompt token 后 lcm 反而 −0.41% | 撤回 |
| "换引擎" | **两个臂都没跑引擎**。只是把 span 文本 + 两条 instruction 拼成裸 LLM 调用，无 `compile()`、无 DAG、无 pruner、无 adapter 截断 | 撤回，重新定义为"prompt 形式对比" |
| `max_tokens=1089` 生效 | **网关忽略**，实测 3182–8153（2.9–7.5 倍超限） | 记为限制 |

**唯一在审计中站住的数字**：v1 的 +22.5pp 在**该语料内**统计显著（MWU 单侧 p≈0.004，Fisher p≈0.0005，长度混淆只解释其中 0.6%）。但它是用一个可游戏、100% 路径、且与调参同一批数据、无留出集的指标量出来的 —— 显著不等于有效。

## 1. 修好的仪器（`bench/anchors.mjs`）

三条硬约束，代码里可查：

1. **去嵌套**：任一锚点是另一条的子串就丢弃，只留极大元素。粘一行前缀拿十几分的路子被堵死。
2. **按类型分层**：单一类型不超过集合的 35%，路径多的语料喂不出纯路径测试。
3. **按事实去重**：同一份列表重复 dump 5 次只算 1 条。

修正后在真实 span 上的产出：

| 语料 | 锚点池 | 去嵌套丢弃 | 最终集 | 类型分布 |
|---|---|---|---|---|

| session-65bd（8065 tok） | 38 | 3 | 24 | path 4, env 5, error 5, hex 4, command 3, uuid 3 |
| eeb08989（8347 tok） | 34 | 1 | 21 | env 8, error 8, command 3, path 2 |

顺带把 span.mjs 的默认产出也换成了这套锚点（`canaryPool`/`droppedNested`/`canaryTypes` 一起落盘）。

## 2. 三臂消融（进行中）

审计指出的关键缺陷是**归因不可识别**：v1 里 basic 与 lcm 至少同时变了 5 个因子（语言、节数、锚点章节、枚举 vs 散文、预算优先级）。要分离出"是不是那条枚举指令的功劳"，得三臂：

| 臂 | 内容 |
|---|---|
| **basic** | 原版 instruction 原样 |
| **basicplus** | 原版 instruction **+ 只追加**枚举锚点那一节 |
| **lcm** | 本仓 `buildInstruction()` |

判据：若 `basicplus ≈ lcm`，收益来自那条 prompt 指令，与引擎无关；只有 `lcm ≫ basicplus` 才谈引擎差异。

**当前进度：N=2（全部是 basic 臂）**

```
basic  rep1  completion 4403  anchor 8/24
basic  rep2  completion 5483  anchor 9/24
```

跑不完的原因：omniroute 网关在本次会话期间多次单请求超时（300s 上限内无返回），一次 program 只能稳定跑 1 次调用。**不编数字，等网关恢复。**
